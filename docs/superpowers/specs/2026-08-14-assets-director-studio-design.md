# 设计与资产、导演工作室复刻设计

## 目标

将 SceneWeaver 的「设计与资产」和「导演工作室」升级为可实际制作的前端工作流，参考 AniKuku 的三栏布局与交互，但使用自主代码与自主视觉，不复制其品牌、图片或私有实现。

## 范围与顺序

### 第一阶段：设计与资产

- 角色、场景、道具三种资产分类与筛选。
- 左侧搜索、创建、列表选择、状态筛选与关联镜头数量。
- 右侧资产详情：名称、状态、描述、标签、视觉参考、基础信息、统计数据。
- 手动创建与编辑资产；用户上传参考图继续保存至本地中文资产库，且可以选择主图、替换、删除网页引用。
- 资产编辑后，已绑定的镜头和导演台中显示的名称、标签、参考图状态实时同步。
- 每种资产都提供“生成/重新生成”请求入口，但在未配置图像 API 时只记录“待接入”的生成任务，不伪造成功。

### 第二阶段：导演工作室

- 三栏结构：Clip 列表、镜头列表、右侧故事板和视频预览区。
- Clip 支持选择、新增、删除、重命名、摘要编辑、按当前锁定剧本归属。
- 镜头支持新增、删除、复制、排序、编辑。编辑字段包括景别、画面、时长、运镜、动作、音频条目、场景、角色、道具。
- 场景限一个、角色和道具可多选。资产选择器复用第一阶段的资产数据，修改立即更新资产关联数量和故事板。
- 故事板以每个镜头作为卡片实时预览，可显示状态（待生成/生成中/已生成/失败）与版本号；无图时显示构图占位卡，不调用外部 API。
- 视频区显示当前 Clip 的生成状态和统一的待接入视频 API 请求入口。

## 数据模型

- `Asset` 增加项目范围的可编辑元数据：视觉参考、创建时间、更新状态、生成状态、关联镜头统计由 `Shot.assetIds` 派生。
- `Clip` 增加故事板版本和生成状态。
- `Shot` 增加单镜头故事板生成状态、排序索引、镜头资产角色（场景/角色/道具由资产类型派生）。
- 所有变更统一走纯函数 `projectMutations`，UI 不直接拼接不同数据源。
- 原创和导入式剧本仍共用当前锁定版本数据；导入式 JSON 的镜头内容不能被本地规则重新拆分。

## 交互约束

- 所有已有的参考图不被任何生成/导入操作覆盖。
- 每个修改按钮必须实际更新项目数据并持久化至浏览器本地存储。
- 删除资产前阻止或提示其仍被镜头引用；默认采用解除绑定而不删除历史本地文件。
- 未接入外部 API 的生成操作明确展示“待接入”，不声称已经生成。

## 验证

- 服务层测试：资产 CRUD、Clip CRUD、镜头复制/排序、资产绑定与解除、故事板状态变化。
- 导入回归测试：完整导演台 JSON 的动作、运镜、音频、类型化资产绑定和参考图保留。
- 全量 Vitest、TypeScript 与 Vite 构建。
- 本地浏览器手工验证资产编辑同步至导演工作室、导演工作室编辑同步至故事板。

## 决策

选择数据优先的完整复刻，而非先做纯视觉页面。原因是本项目的价值在于资产、镜头和故事板可以串联修改；视觉布局会在每个功能模块完成时同步向 AniKuku 的信息层级靠近。
